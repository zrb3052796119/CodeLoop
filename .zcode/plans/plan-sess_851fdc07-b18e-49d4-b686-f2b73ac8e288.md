## 阶段 1：修复 Workflow authority result 的 Conversation 一致性
### 实现
1. 抽取一个中立的最终响应投影 helper（避免 `conversation.py` 与 `agent_runtime.py` 互相导入）：
   - 当前 Turn 内优先取非空普通 assistant 文本；
   - 若不存在，再取该 Turn 内最后一个 authoritative `tool_result` 文本；
   - 不能回退到更早 Turn 的 assistant，避免多轮 CLI/Dashboard 回显旧答案。
2. 让 `ConversationTurnService._turn_result()` 使用该 helper，并返回 result message index/role，而不再硬编码只接受 `role=assistant`。
3. 扩展 Session commit marker 的解析/写入以兼容两种终态：
   - 保持现有 v1 assistant marker 的恢复兼容；
   - 为 authority `tool_result` 增加明确的结果索引/类型信息，或在现有 marker 约束内安全识别紧邻的 tool result；
   - `_authoritative_result()` 必须校验 marker 指向当前 Turn、tool id/消息形状和非空内容，不能接受任意历史 tool result。
4. 修复 `_reconcile_active()` 和 `_terminal_result()`，使已提交的 authority tool result 能恢复为 completed，而不是误标 interrupted。
5. 统一 Headless、CLI、TUI、Dashboard 的 projector，移除各处“扫描整个 Session 最后一个 assistant”的 ad-hoc 逻辑。
6. 保留 commit fence、Session CAS 和已提交变更的 fail-closed 语义；不把失败的普通 tool result 伪装成成功。

### 测试
新增/扩展：
- authority tool_result-only 的 Conversation turn 成功提交；
- 已提交 turn 重启后可恢复；
- 历史 assistant + 当前 tool_result 时只返回当前 turn；
- 当前 turn 没有有效结果时仍按失败处理；
- 普通 assistant 路径和 authority 路径均不破坏旧 marker 兼容。

## 阶段 2：统一文件路径与归档工具权限
### `diff_viewer`
1. 在 `minicode/tools/diff_viewer.py` 对模型提供的路径统一调用 `resolve_tool_path(context, path, "read")`。
2. 只有 `__file__` 才读取磁盘；直接提供的 before/after 内容不要求文件存在。
3. 拒绝绝对路径、`..` 逃逸、外部 symlink、内部 Memory 存储目录，并对错误信息做相对路径/脱敏处理。

### `archive_utils`
1. `gzip_compress`、`gzip_decompress`、`tar_create`、`zip_create` 的 source/destination（包括自动推导的默认 destination）全部走统一 resolver 和 operation checkpoint。
2. suffix 补全后重新做最终路径校验，避免先授权再变形绕过 containment。
3. 保留现有 tar/zip 成员 traversal、symlink/hardlink 防护；补齐 source 目录遍历中的外部 symlink 防护。
4. 增加 bounded extraction：成员数、单成员/聚合展开字节、绝对 deadline/cancellation；按 chunk 计数，超限前停止写入并清理临时/部分输出。
5. 将功能审计从静态“固定报错”改为真实 probe 驱动：所有越界/预算 probe 通过后才移除 `SEC-002`/`SEC-004`。

### 测试
新增/扩展：
- gzip/tar/zip create/decompress 的绝对路径、`../`、symlink destination/source；
- 默认 extraction destination 的权限校验；
- zip/tar 成员路径和链接安全；
- member count、aggregate byte、deadline/cancellation 超限及清理；
- `diff_viewer` 工作区外读取必须失败，工作区内 `__file__` 仍正常。

## 阶段 3：修复命令和后台任务生命周期
### `run_command`
1. 提取共享的 process-group termination helper，复用 `subagent_supervisor`/`deterministic_verifier` 的语义：POSIX `SIGTERM -> grace -> SIGKILL -> wait/reap`；Windows 保留 terminate/kill，并用新进程组标志。
2. PTY 和 fallback 都改用 absolute monotonic deadline，不把完整 timeout 在每次输出后重新计时。
3. 每轮读取/等待前检查现有 Turn cancellation token 和 task deadline；取消/超时返回明确的 typed termination reason。
4. `openpty`、`Popen`、master/slave fd 关闭、stream drain、wait/reap 全部放入异常安全的 `finally`；Popen 失败也不能泄漏 fd。
5. 不在工具返回后继续保留由该命令创建的进程组；避免只 kill shell 主进程。

### `background_tasks`
1. 将 `can_start_new_task()` 改为带锁的原子 slot reservation；Popen 失败回滚 reservation。
2. 记录 cwd、开始/结束时间、退出码、终止原因、process group/session identity；避免只靠裸 PID 判断状态。
3. 增加幂等 cancel/shutdown API，取消和应用退出时清理全部后台进程组并 reap；取消后禁止新任务。
4. registry 的状态迁移和 callback exactly-once 使用 `RLock`；在主程序退出 finally 接入 shutdown。
5. 明确 Windows 进程树清理能力；不把 POSIX killpg 误用于 Windows。

### 测试
新增 `test_run_command_lifecycle.py` 和 `test_background_tasks.py`，覆盖：
- 持续输出命令遵守总 deadline；
- cancel 立即终止主进程及 child/grandchild；
- stdout/stderr 不阻塞、Popen 失败无 fd 泄漏；
- 超时/取消后的 process group 不存活；
- 并发启动不超过 max slots、Popen 失败回滚；
- callback exactly-once、cancel 幂等、shutdown 拒绝新任务。

4. 增加 runtime import-closure 检查，明确报告“被 tracked 代码导入但未进入 Git archive 的模块”；本次不擅自删除或覆盖当前未跟踪模块，若报告仍提示它们缺失，将作为发布前必须纳入提交的明确阻塞项。
