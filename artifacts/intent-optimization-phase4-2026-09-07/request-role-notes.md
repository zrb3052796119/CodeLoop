# 第四轮：请求角色与动作范围

本子任务修改 `minicode/intent_request_roles.py`；parser 的三个整合 patch 均由 root 应用。没有读取 U50 新盲测内容。

## 已实现

- 完整建议性问句、第三人称对象效果问句、名词主语用途疑问分别识别为只读请求范围。礼貌的直接请求及宾语前置 `帮我` / `please be` 请求保留动作权限。
- parser 依据整个当前输入的原始偏移处理候选，避免分句吃掉问号后丢失请求角色。同一问句已有只读候选时，删除其被讨论的动作候选；否则转换原动作，或在无动作词的明确问句中补充读取。
- 逗号或括号中明确的新请求（包括 `顺便` 引入的动作）同时终止只读范围并参与实际分句。后续命令独立匹配，保存真实文件实体与原文偏移。
- `is_bounded_readonly_request` 限制完整只读语义框架中的模型 proposal。讨论性请求及有明确语气词的口语疑问仍可交给模型判断标签，禁止模型将这些请求升级成 CREATE / UPDATE。

## 行为验证

Root 独立开发 probe 从真实旧版 15/26 提升到候选 26/26。已知 T05 / T11 从写操作变为 EXPLAIN / READ；无需模型调用。新的提问识别也恢复 T07 / T16 的肯定读取。

独立审查发现并修复了本轮实现中的三个回退：逗号后真实命令被宽范围覆盖；宾语前置礼貌请求被误当效果疑问；已有解释候选时生成重复 READ。审查新增的四条逗号/括号命令，现均获得 READ 加真实 DELETE / UPDATE，并正确绑定文件实体。

最终 public API 测试由 root 编写在 `tests/test_intent_request_roles_phase4.py`，本子任务执行同字节真实 baseline 证明。机器结果见 `roles-proof.json`；最终测试文件 SHA 以该文件为准。

## 已知边界

- 这是有界语法范围，不是通用中文句法分析。未识别的名词角色仍可能影响语义兜底权限。
- 独立审查中的 `这段说明得怎么看呀？我暂时不打算运行测试。` 在旧版已错判 EXECUTE；新入口仍可能接受错误的模型 UPDATE / CREATE。`说明` 被共享动作词识别，导致有界名词主语框架保守退出。本轮按收口约定记录，不继续增加单题词条。
- 固定恶意 proposal 证明本地 admission 行为；真实模型端到端提升必须由 root 的冻结评估衡量，不能用这些开发 probe 推断新盲测提升。
