# 意图识别第四轮优化与评测

日期：2026-09-07。**已修复一批讨论/疑问误写、否定范围及分析请求漏识别问题；最终交付代码通过 2,697 条相关测试。但独立新题尚未证明准确率提升。**

## 本轮交付

- 用完整请求范围判断动作角色：询问“应该怎样重构”“命令会修改文件吗”得到只读操作；“能帮我重构吗”、宾语前置的礼貌请求以及后续明确修改仍保留动作和文件目标。
- 分离正向请求与相邻禁止操作，补齐“不准备／不打算”等否定表达，并保留真正的条件命令和明确重启请求。
- 对识别出的讨论范围限制 LLM 提案，拒绝把讨论改为 CREATE／UPDATE；修复过程中增加了真实文案修改、括号内命令等反例，避免过度拦截。
- 盲测发现本轮分句导致 U10 漏掉语义兜底。交付前单独修复：事实背景与“先分析”保持相连，假设范围仍可独立结束。

生产改动只有 `intent_parser.py`、`intent_request_roles.py`、`intent_negation.py`，另更新说明文档。没有执行样本描述的操作，没有修改全局 LLM 配置。

## 哪些提升由代码带来

纯规则旧题的七个改善为 T05、T07、T09、T11、T16、T19、T43，没有严格得分回退。线上旧题 133→147 的全部增量不能归因于代码：本次只有 N30 一次超时，过去部分超时题此次成功返回，模型提案也有变化。

对 230 题，在真实优化前源码与冻结评测源码之间重放三套相同提案（空提案、前次已接纳提案、本次已接纳提案），共 690 对离线比较。新题中：

- **U10 是代码引入的召回回退。** 分句把事实背景和分析请求拆成两个未覆盖片段，兜底因不能选出唯一目标而跳过；相同 DEBUG／ANALYZE 提案在原版可接纳。
- U43 恢复了肯定 EXPLAIN／READ，但冻结预期是 DEBUG，因此不计完整通过。
- U07 的提升、U27 与 U47 的下降，在相同提案下两版行为一致，属于线上提案差异。

新题也有标签口径争议，例如 U05 的 REVIEW／COMPARE、U28 的 CODE／RENAME、U40 的 CODE／DELETE。它们仍按原始标签记失败，没有事后放宽分数。其余失败包括没有肯定请求、遗漏第二动作、领域误判及真正的只读误写，不能全部归为标签争议。

评测源码完整保存在工作目录的 `evaluated-candidate/`，哈希见 [evaluated-source-freeze.json](evaluated-source-freeze.json)。最终交付哈希见 [delivery-source-freeze.json](delivery-source-freeze.json)，额外修复仅为 parser 中 16 行分句保护，见 [delivery-regression-fix.patch](delivery-regression-fix.patch)。

## 验证与真实模型记录

新增测试共 98 条；最终相关回归 **2,697 通过（59.60 秒）**，Ruff 关键检查通过。

| 同字节测试组 | 最终通过 | 真实修复前快照 |
| --- | ---: | ---: |
| 请求角色与模型接纳 | 56 | 29 失败、27 通过（第三轮最终源码） |
| 正向请求与否定范围 | 30 | 15 失败、15 通过（第三轮最终源码） |
| 分析背景回退修复 | 12 | 3 失败、9 通过（本轮冻结评测源码） |

失败均核验为行为断言，最终测试哈希与证明文件一致，没有将导入或设置错误计作修复证据。日志与证明见 [delivery-regression.log](delivery-regression.log)、[proof-integrity.json](proof-integrity.json)。

真实模型为配置中的 `glm-5.3-flash`，使用智谱 `open.bigmodel.cn` 接口。超时 5 秒、最低置信度 0.72、最大输出 512 tokens 等设置保持不变；只在评测内存中开启语义兜底。六组新线上运行顺序执行，共解析 280 次样本，实际 **111 次 model.started、110 次 completed（均有 provider usage）、1 次 failed（N30 超时）**；发生调用的样本耗时中位数约 1.31 秒。完成事件不等于解析正确；未对未定价模型臆测金额。

外部调用最初被自动审批拒绝。补充逐条合成数据审计、实际 111 个候选载荷、源码/数据哈希和明确目标服务后重新获准；没有绕过审批。发送的是冻结题目及其合成上下文，不包含预期标签、评分说明或仓库源码文件。详见 [payload-audit.md](payload-audit.md)。

## 尚未解决的主要问题

1. 新 U01、U13、U16 仍会把只读问题误判为写入，说明自然语言角色覆盖仍不足。
2. 规则已经错误命中时，较高的规则置信度常使 LLM 没有纠错机会；仅扩展兜底入口不能解决所有误判。
3. 多步骤请求、上下文诊断和意图类别边界仍不稳定。需要先统一分类约定，再评估路由效果。
4. 模型接纳限制仍是有限语法覆盖。“说明得怎么看”等未识别口语，以及恢复后的“事实背景＋分析”原有模型入口，仍可能接纳错误的写提案；本轮没有宣称所有只读表达都已受到完整约束。

下一轮应优先处理错误规则命中的复核机制和复合请求的统一表示，并使用另一批未见样本检验。独立核验与逐题证据见 [results-review.md](results-review.md)、[comparison.json](comparison.json) 和 `runs/`；所有归档文件哈希见 [manifest.json](manifest.json)。
