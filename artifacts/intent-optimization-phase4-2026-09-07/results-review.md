# 第四轮结果与交付版本独立复核

**评测版改善了既有开发集，但新 50 题没有整体提升，并引入了 U10 的模型兜底召回回退。该回退已在评测结束后单独修复；历史线上分数保持原样，不能套到修复后的交付源码。**

本复核没有改题、改标签、改计分器或修改生产实现。规则和真实 LLM 两种模式共 920 条前后记录的主意图标志、完整 issue 列表与只读判定均独立重算匹配。这里的“全部标注通过”不是完整参数精确匹配，也不是任务执行成功率。

## 线上下降的原因：代码回退与模型提案差异分开

新题线上改善 U07，回退 U10/U27/U47。对新 50 题的空提案、前次已接纳提案、后次已接纳提案分别固定，在两份真实源码上作 150 组配对比较：

- **U10 是代码因果回退。** 新增分句将事实背景和“先帮我分析”拆成两个未识别子句，而现有 fallback 只接受一个未覆盖子句，因此不再调用模型。同一个 DEBUG/ANALYZE、confidence=0.82 的提案，真实旧版调用一次并得到 DEBUG，评测版调用零次并得到 UNKNOWN。独立另起进程复现了这一点，不能归为模型波动。
- U27 的 DEBUG/UPDATE 与 CODE/UPDATE 差异、U47 的 CREATE+UPDATE 与仅 UPDATE 差异、U07 的 QUESTION/READ 与 EXPLAIN/READ 差异，在相同提案下前后源码行为相同，属于两次线上提案差异。
- U43 的代码行为从 UNKNOWN 变成 EXPLAIN/READ，但冻结标签要求 DEBUG，前后都没有严格通过。

全 230 题 × 3 组固定提案共 690 组配对也已审计。唯一出现相同提案下严格分数回退的题是 U10。固定提案重播证明入口与接纳变化，不是新的真实模型成绩，也不足以证明生产分布泛化提升。

## 标签争议不能替代真实失败诊断

U05 的 REVIEW/COMPARE 合理表达比较重构方案代价，但冻结预期只接纳 REFACTOR/EXPLAIN；U28 的 CODE/RENAME + CODE/UPDATE 保留了重命名与改引用，而冻结重命名必须 REFACTOR；U40 的 CODE/DELETE 与冻结 CONFIGURE/DELETE 主要是类型口径差异。仅标注争议，**保留原分**。

U07 的 QUESTION/READ 与 EXPLAIN/READ 也是近邻表达，而本题冻结的 QUESTION 动作仅接受 ANALYZE，导致线上前值失败。下一轮可在编题前明确类型别名与动作兼容约定，不能事后修改本轮标签以抬高结果。

新题规则模式的 41 条失败中，25 条没有识别到肯定请求、3 条实际只读错写、3 条上述类型争议、2 条缺第二动作、8 条其他领域/主意图/动作精度问题。主要问题不是标签争议。线上仍有 U20/U23/U45 漏复合步骤，U30 把执行测试变成分析，U33 缺移动动作，U37 从文档中的“字段改名表”多拆出重命名等实质缺陷。

## 运行真实性与版本证据

本轮六次新 live 严格串行，实际 **111 次 model.started、110 次 model.completed、1 次 model.failed**；110 次完成均携带 provider usage，唯一超时为 **N30**，新 U 两次没有超时。完成事件的 `toolCallCount` 均为 0。完成和 usage 证明请求完成，不证明分类正确；成本记录为不可用，不能声称免费。

全部前后配对的已记录 runtime 完全一致：`custom` / `glm-5.3-flash`，timeout=5 秒、最低置信度 0.72、输出上限 512 tokens、输入预算 4,000 字符、JSON 模式、reasoning=low。原始评分器与数据、实际来源源码哈希均验证有效。动态出站载荷另见 `payload-audit.md/json`。

线上评测版本现完整保存于 `evaluated-candidate/`，哈希在 `evaluated-source-freeze.json`。原始 20 组前后/模式结果目录的 results、summary、freeze 共 60 文件，以及原始固定提案结果，经再次检查均未变更。

## 评测后的交付修复，单列验证

交付源码相对 `evaluated-candidate` 仅在 `intent_parser.py` 增加 16 行分句保护：普通事实背景与后续分析保持相连，仅在已有假设前缀成立时关闭该假设范围。它恢复 U10 的原有模型入口，没有改动题目或重算历史线上分数。

独立核验交付版相对评测版的 690 组相同提案比较，**只改变 U10 的三个提案组**：调用数从 0 恢复到 1，固定正确诊断提案恢复 DEBUG/ANALYZE。其余 229 题的同提案解析与请求均不变。同字节 12 条回归测试在评测版 3 失败、9 通过，交付版 12 通过；失败均是目标“模型入口不应丢失”断言，无导入或设置错误。全量相关回归日志为 **2697 passed**。

需要保留限制：独立对真实原基线、评测版、交付版分别注入错误 CODE/UPDATE 或 CODE/CREATE，交付版与原基线一样仍可能接纳错误写提案。恢复原有入口不等于完善了所有只读语义边界。

**交付修复没有重跑真实模型，也没有新的盲测成绩。** 25/50 → 23/50 专属于封存评测版；不能改写为交付版的准确率。完整机器复核记录、源码/结果哈希、U10 三版本提案证据和未解决边界见 `results-review.json`。
