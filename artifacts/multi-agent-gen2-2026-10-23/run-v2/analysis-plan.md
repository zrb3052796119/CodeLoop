## 离线有效性与交付标准

对三题分别以相同解释器、完全相同的隐藏 oracle 字节验证：未改动基线的公开检查通过；基线隐藏 oracle 因目标行为失败；真实参考源码通过公开检查与隐藏 oracle。参考投影为真实父源码加上 sourcePaths 的真实修复提交完整文件，逐文件记录前后 SHA-256。不存在以新造 bug 充当真实基线的操作。

受测 Agent 仅获得公开基线、问题陈述、精确写范围和公开兼容测试。每题必须新增 `tests/test_eval_regression.py`，独立、无筛选地执行该文件；至少收集并通过一项测试，全部已收集测试的 setup/call/teardown 必须成功，skip、xfail、xpass、零收集、缺文件或超时均失败。不得修改公开测试。成功还要求实际改变授权生产源码、隐藏 oracle 通过、范围合规、完整用量、清理完成；explicit 另须真实 Executor 和所属 workflow 的宿主送达证据。

## 冻结运行条件

- 模型固定 `glm-5.3-flash`，temperature=0，HTTP 内部重试=0；主子角色使用同一实际路由，禁止换模型救数据。
- 角色累计调用限制显式固定为 explore=0、plan=0、general=0；0 表示不额外施加角色累计上限，仍受共享 40 次请求、500000 token、600 秒和生产 Assignment 约束，不表示获得无限物理请求。
- 每格父子共享最多 40 次实际请求、500000 token、600 秒 Agent 执行时间；输出上限 8192 token，连接/空闲/单请求超时分别 30/120/300 秒；成本安全上限沿用 5 USD。外部裁判 120 秒另计，不延长 Agent 的 600 秒。
- 3 题 × 2 组 × 1 次，共恰好 6 格。组别 `single`、`explicit`；种子 20261023，具体固定顺序写入 manifest。串行运行，不以某格成功为后续开跑条件。
- single 使用既有本地编码工具；explicit 父协调者仅使用 task/todo，首次直接提交 workflow，不先支付外部 Plan。异常、真实失败后的分析等仍按冻结生产策略发生并完整归因。
- 完整宿主源码、harness、包资源、依赖声明、逐文件 inventory、任务、离线证明与 manifest 在运行前冻结并提交。运行从校验后的宿主副本执行；不从继续变化的活工作区导入生产代码。
- 当前宿主包含本轮 Phase 0/1 修复及用户此前未提交的共同背景修改。快照记录实际字节，不把其他工作按源文件夹带进本轮提交，不声称它是“只改 Phase 1”的干净因果实验。两组使用同一宿主。
- 凭证保持在本地配置，不写进任务、日志、快照或 Git。实际路由身份以非秘密 fingerprint 绑定。角色调用上限与其他影响运行的显式配置由 manifest 固定，不因私有环境改变。

运行命令必须指明已包含冻结材料的真实 Git commit。父入口与直接 child 入口都在 provider 初始化之前核验提交中的字节。提交 SHA 作为运行参数及执行证据记录，避免 manifest 对自身 commit 的循环引用。

## 预先固定的工程门

必须有完整六格和有效独立审计，再按以下门判定：

1. 总成功至少 4/6。
2. single 和 explicit 各至少 2/3。
3. 每题至少 1/2。
4. 既有范围、清理、账本、用量、新增回归测试和真实送达标准全部执行，未知用量不记零。

同分如 3/3 对 3/3 也可继续。本六格不要求 explicit 严格高于 single，也不新增协议税比例门槛；这些遵守已接受的修复方案 v1.1。报告 Plan/Analyst/Executor 分开的绝对请求、token、耗时及非 Executor 请求占比，另列 Executor 获得实际编辑机会的试次数。比例本身不等同全部协议成本。

每格失败、超时、预算拒绝、协议拒绝、未知用量和原始证据保留。不调模型、不换题、不补抽、不挑最好轮次。已有调用证据的格不得重跑。若进程清理失败等导致不能继续，保存已发生的全部记录，标明评测不完整，不把未跑格当成功，也不静默补一轮。

过门才进入 Phase 2；未过门时结论固定为：**当前模型、任务集、预算和协作策略组合尚未证明收益。** 不把失败单独归因于模型或协议。此时冻结写路径协作的后续增强，保留只读子代理与快照回写产品能力。
