# 意图识别 50 题实测报告

测试日期：2026-09-07。结论：**明确的代码与测试指令有一定基础，但自然表达、撤回、假设和上下文理解还不稳定；目前不足以单独承担可靠的任务或动作判定。**

## 实测结果

| 指标 | 结果 |
| --- | --- |
| 主意图符合执行前的人工预期 | **26/50，52%** |
| 所有已标注要求通过 | **23/50，46%** |
| 将两条合理近义分类计为可接受后 | 主意图 **28/50，56%**；已标注要求 **25/50，50%** |
| 有明确任务却返回 unknown | 14/50 |

| 解析异常 | 0 |
| 已有针对性回归 | **333 passed，0 failed，exit code 0** |

“所有已标注要求”检查主类型、必要操作、否定极性，以及各题明确标注的动作、文件实体、只读属性和操作顺序；不是每个输出字段完全匹配，也不是任务执行成功率。近义口径的两题为 C40（question/read 与 explain/read）和 C47（code/update 与 refactor/update）；原始题库与原始评分均未更改。C33 的“定位原因”被归为 explain/read，独立评审认为有灰区，单独列为类型精度问题；即使额外接受此题，全部已标注要求也仅 26/50。

本次是人工设计的新题抽样，不能推断真实用户流量的总体准确率。30 条常规题为 15/30 通过；20 条独立编写的边界与上下文题为 8/20 通过（原始冻结口径）。前 24 条常规开发题排除问答、闲聊、记忆、系统操作后，仍为 15/24 通过。

### 优先处理的问题

1. **把描述、风险或假设当作动作。** C35 的“指出可能误删文件的地方”被拆出 `code/delete`；C38 的“假设有人把 api.py 删了”也得到肯定的 `code/delete`。C17 明确要求审查 PR，却输出 `debug/update`。
2. **撤回不生效，否定范围越界。** C32“修复……先取消，现在只解释”仍保留肯定 `debug/update`。C35 已撤回的测试仍输出 `test/create`。C34“别记住这段对话。直接解释……”却把解释本身标成否定。
3. **自然说法漏识别。** C02“给登录接口加上……限流功能”、C06“支付扣了两次钱，查一下哪里出了问题”、C09“拆成几个职责单一的小函数”都输出 `unknown`。
4. **任务与对象丢失。** C45“修改日志级别，然后运行测试”只剩 `test/execute`。C46“继续审查后一个文件”和 C48“再加一个 None 输入的用例”分类正确，但没有继承 `payment.py` / `utils.py`；C50 无法承接文档修改。
5. **文档材料被解析成实际配置。** C21“更新 README.md，补上 Docker 部署步骤”得到 `code/update + configure/update`，没有 `document`；C15 只问配置文件在哪里，却得到 `configure/update`。

上述修改/删除均是**解析器输出的建议性操作**。本次没有运行 Agent、执行这些操作或验证下游权限控制，因此不能据此断言系统实际会修改或删除文件。

### 可接受与有争议的分类

- C40 对“迁移是什么意思”输出 `question/read`，没有触发迁移操作。尽管冻结预期是 explain，可作为合理近义结果。
- C47 对“按这个方案改，签名不变”输出 `code/update`，且继承了 `cache.py`。丢失重构子类型，但任务和修改目标基本正确。
- C33 保留禁止重构与测试，目标和只读属性正确，把诊断原因归为 `explain/read`。这是类型精度灰区，严重程度低于动作反转或目标缺失。

## 当前实现与测试方法

实际配置 `load_runtime_config('.')` 的 `intentSemanticClassifier.enabled=false`。因此本次直接运行仓库根包 `minicode.intent_parser.IntentParser.parse`，与当前生产路径调用的 `parse_intent` 使用相同实现；50 次输出均为 `semantic_status=disabled`。另选 6 条代表性失败通过公开 `parse_intent` 入口复现，除时间戳外详细输出完全一致。

生产入口可见 [skill_routing_turn.py](../../minicode/skill_routing_turn.py#L145)、[intent_parser.py](../../minicode/intent_parser.py#L9813)；配置关闭时不构造适配器，见 [intent_semantic_classifier.py](../../minicode/intent_semantic_classifier.py#L895)。上下文使用 `IntentContext.from_messages`，仅传先前 user/assistant 消息，不把当前问题放入历史。

30 条常规题由主评估者预先标注，并由另一评估者在看不到输出时复核。20 条边界题由独立评估者在不读实现、不读已有题库、不调用解析器的条件下编写。合并后，在第一次运行前冻结题目、预期、脚本和关键源文件 SHA-256。运行后没有改题、改标签或修实现再重算原始分数。

主意图依据实现的动作优先级选择，不总是自然语言中的第一步。因此多意图题接受合理的多个主类型，并检查必要步骤；三条明确序列题另检查顺序。纯模糊 C49 返回 unknown 计为通过；没有把所有 unknown 一概判错。

规则 confidence 是固定计算值，不是经验正确概率。例如 C15 错误的 `configure/update` 仍有 0.92。不要用返回的高 confidence 抵消本次错误证据。

### 速度

本机 Python 3.12，50 条输入，单次串行测量：解析器实例初始化约 **36.83 ms**；解析耗时中位数 **1.36 ms**、P95 **2.62 ms**、最大 **2.89 ms**，总计 **70.36 ms**。不包含模型调用、Skill 排序、Agent 执行或用户请求端到端耗时。这是短句样本的测量，不能代表长文本和并发性能。

### 回归验证

运行 `python3 -m pytest -q` 并指定以下四个文件：`tests/test_intent_parser_v2.py`、`tests/test_intent_runtime_integration.py`、`tests/test_intent_constraints.py`、`tests/test_intent_semantic_classifier.py`。共 333 项通过，耗时 1.57 秒，退出码 0，无真实目录污染报告。语义相关回归使用测试替身，没有真实模型调用。

既有回归通过、新题表现偏低，说明既有测试绿灯不足以代表当前自然语言覆盖。此次证据不足以单独证明训练过拟合或真实生产准确率下降。

## 改进顺序建议

先处理撤回、假设、被审查内容与真实动作的边界，再修跨句否定范围；这是比增加同义词更优先的错误类别。随后处理中文自然动词表达、文档/配置区分和多轮目标继承。

LLM 兜底应单独评估。当前它关闭；开启后的效果本轮没有实测。而且当前 fallback 主要接手未识别请求或未覆盖子句，C15/C35 这种已经错误命中的操作不保证会送给模型纠正，不能把“开启兜底”当成这些失败的已验证修复。

这 50 题可以保留为回归集；若按这些题修复，下一轮应另做新题检验泛化。
