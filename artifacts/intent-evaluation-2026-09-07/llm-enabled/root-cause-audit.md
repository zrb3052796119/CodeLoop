## 三个最重要的架构原因

### 1. 规则一旦覆盖分句，就被当作最终结论，模型只能追加

`_semantic_fallback_target`（`minicode/intent_parser.py:8302`）只接管全未识别请求，或唯一未覆盖的肯定分句；操作 span 有交叠便算覆盖。`_merge_semantic_operations`（同文件 8357 行）仅合并追加，不提供替换、撤销或冲突裁决。规则置信度来自手工映射（9136 行），并不是实测正确概率。

因此 C15 的“找配置文件”已被错判 `configure/update`，C17 的“审查异常处理”已被错判 `debug/update`，模型根本没有机会纠正。LLM 本轮仅调用 18/50 题，不能据整体 62% 判断“模型理解只有 62%”。

优先路线：将规则输出改成候选证据；对于写动作与只读措辞冲突、撤回/假设、歧义分句、未解析指代等情形，触发完整请求级复核。允许复核撤销或降级错误肯定候选，同时保留明确禁止事项；执行权限仍由独立的本地约束层决定。单纯降 LLM 置信度阈值或延长超时不能修复这 12 条被跳过的问题。

### 2. 分句、作用域、上下文和主目标缺乏统一表示

C32 把“修复……先取消”保留为肯定修复；C34 把前面的“别记住”否定扩展到后面的解释；C35 把“指出可能误删文件的地方”拆出 `code/delete`；C38 把假设条件变成肯定删除。这些是请求/描述/限制的关系错误，不是缺几个同义词。

主操作选择还会放大误判：`_ACTION_PRIORITY`（5335 行）赋予 delete=100、create/update=80、read=40；`_select_primary_operation`（9145 行）优先按动作权重，再按出现顺序，最后才比较置信度。于是误抽出的删除压过了正确审查，过期修复压过当前解释。C33 中模型只看到未覆盖的“只阅读现有代码”，返回 `search/read`；最终将准备步骤选作主任务，真正的“分析缓存命中率下降原因”仍被规则归为 `explain/read`。

上下文也有缺口：C46 “后一个文件”、C48 “再加一个用例”均已识别动作，却没有继承明确的目标文件。C50 没有操作候选；本地无 provider 探针确认，整句 fallback target 因“其他内容不动”被 `is_clause_negated` 判定含否定，导致全部跳过（5998–6017 行）。

优先路线：先抽取当前目标、候选操作、肯定/否定/撤回/假设/引用状态、约束作用对象、顺序与前置关系，再选择主目标；将缺失目标解析作为独立阶段，不以“已经命中动作”为完成条件。上下文保留有序实体和活动任务，解析“后一个”“这个方案”“那一行”，而非笼统合并所有历史文件。最先处理 C15/C17/C32/C35/C38 这 5 条“预期只读却出现写/删建议”的边界错误。

### 3. 模型通道既有资源问题，也有表达能力上限

默认 1.5 秒下 18 次调用全超时；10 秒下触发模型的题耗时中位数 5.59 秒。7 次无效均报告输出 256 tokens，恰好达到上限；其中 6 次内容为空。剩余失败中的 5 次无效全部为空且达到上限。这是强烈的输出预算/返回形式信号，但日志未保存原始 completion，不能断言全部由推理 token 或 JSON 截断造成。

`IntentSemanticClassifierConfig`（`minicode/intent_semantic_classifier.py:170`）提供输出上限 256 tokens，允许范围最高 1024；调用设置 temperature=0、零重试（约 532 行）。这些可通过受控参数实验验证，例如保持其他设置不变比较 512/1024 token 上限，记录是否有最终内容、有效结构比例、延迟和成本。不要同时改多个因素后归功于某一个参数。

但当前模型 schema 只允许 `intent/action/confidence`（同文件 90 行），不能返回实体、作用域或否定；`SEMANTIC_INTENT_ALLOWED_ACTIONS`（`minicode/intent_parser.py:5311`）也不含 `system`。因此 C30 清空会话即使输出恢复完整，当前兜底仍无法合法返回 `system`。需在明确受限的系统命令解析中覆盖，或扩展经过验证的结构；加 token 不是全解。

## 建议实施与验收顺序

1. 保留现有 50 题为回归，增加按上述错误机制编写、提前冻结预期的改写题与多轮题。将主意图、动作边界、否定/撤回、目标实体、步骤完整性分项统计；近义标签在新增测试开始前确定。单独记录错误写/删建议，不能被总准确率抵消。
2. 同时推进两项小步工作：修复错误写/删候选及否定作用域；排查真实模型结构化返回预算，保留预算与响应校验。前者需要逻辑修改，后者先做参数实验。
3. 引入请求级复核和完整语义结构，使模型能够纠正规则误判，并补充实体/指代解析；保留禁止事项的独立校验。主意图按用户最终目标选择，动作影响程度作为另一维度报告。
4. 在新增冻结题上与原配置配对对照，至少重复运行观察模型波动，同时看分项准确率、错误写动作率、结构有效率、P50/P95 延迟及实际可计量费用；通过后再调整默认开关和路由范围。

这轮是 50 条合成请求的单次运行，没有验证下游 Skill 选择或执行行为，也不代表线上流量准确率。这里不预测优化后的通过率。
