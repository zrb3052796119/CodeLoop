# 反思模型超时与空输出修复

反思调用已恢复正常生成。相同的 **15 秒、1,200 token** 限制下，完整合成复跑的 **10 个片段全部返回并解析成功**：没有超时、空正文或输出截断，中位耗时 8.77 秒，最长约 12.03 秒。

## 问题原因

1. **请求配置不匹配。** 当前 GLM-5.3-Flash 的官方参数默认 `reasoning_effort=max`，且思考不能关闭。代码已经识别该官方路由支持 `low` 和 JSON object，但专用反思 client 没有传这两个控制。高思考量与反思的小输出预算、短超时不匹配。旧记录的 1,200 token/空正文没有 finish reason，不能声称已证明这些 token 全部用于思考。[官方 API 参数](https://docs.z.ai/api-reference/llm/chat-completion)
2. **诊断信息丢失。** 底层已有停止原因和思考内容信息，反思 wrapper 却只取正文。因此正常结束、输出额度耗尽、真正空响应无法区分。
3. **局部超时被当作父任务截止。** 单次提供方超时沿用 `ModelCallDeadlineExceeded` 向上抛，导致同一任务的后续片段也未处理。
4. **标题合同没有传给模型。** 请求修复后约 6.6 秒就产生了 JSON，但模型自然改写了任务标题；解析器一直要求标题逐字一致，生成 schema 却没有声明此要求。

## 已实施的修复

- 只在适配器明确支持时，为反思请求传 `reasoning_effort=low` 和 `response_format=json_object`；保持无工具、单次输出上限和零重试。其他路由不猜测参数支持，普通主 Agent 请求不变。没有误发该模型不支持的“关闭思考”参数。
- 在每次生成的 schema 中将 `task_summary`、`outcome` 绑定为宿主的固定值，提示模型照抄；解析器仍然严格拒绝错标题和错误 outcome。
- 透传白名单 `stop_reason` 与 nullable `reasoning_present`，不保存思考正文。`length`/`max_tokens` 单列为 `output_limit_reached`，即使残片碰巧构成合法 JSON 也不准入。
- 提供方局部超时转换为 `provider_timeout`，预算正常结算、继续下一个片段；真正的父任务截止和用户取消仍然终止执行。
- 补齐候选投影中同目标的后续失败复跑，保留对应 invocation 与事件位置；先按目标和时间关系筛选，再取最多 4 项，截止于后续独立恢复链或成功 followup。失败记录仍为失败，不改变 candidate 身份或通过验证的绑定。提示模型不能把“输入里没显示”写成“没有执行”，适用条件只能使用已观察事实。

## 同预算真实复跑

| 结果 | 修复前 | 修复后完整批次 |
| --- | --- | --- |
| 可解析片段 | 0 / 10 | **10 / 10** |
| 15 秒超时 | 9 次，另 1 段未执行 | **0** |
| 空正文 / 截断 | 延长到 60 秒的额外诊断仍为空 | **0 / 0** |
| 结构准入 | 0 | **6 条** |
| 候选被错误确认 | 无可评输出，不能算质量结论 | **0**，4 条保留观察 |
| 耗时 | 15 秒批次全部触顶 | 中位 **8.77 秒**，最大约 **12.03 秒** |

修复后批次报告 provider 用量共 19,314 input、4,322 output tokens；费用仍未知，没有套用其他模型价格。两次先行诊断分别用于验证请求控制和标题合同，报告独立保留。

6 条准入经验中，4 条为 `recovery/confirmed`，2 条为保守的 `warning/inferred`。独立人工式审查未发现根因越级、跨片段借用或阻断性事实错误。相比规则，主要改善是适用条件、验证范围和检索表达；这个小样本还不能证明普遍优于规则。

## 候选语义复核与定向修复

完整批次的 4 个候选都被留在观察层，未准入正式经验；其中两条观察存在需要修正的表达。`retry-still-failed` 的输入遗漏了后续失败复跑，导致模型声称“没有执行验证”；`report-timeout-budget` 将“超时设置太短”这一未证实原因写入适用条件。

补全失败证据并收紧指令后，两案例在相同预算下定向真实复跑，**2 / 2 返回并解析成功**，分别约 8.02 和 7.89 秒，停止原因均为 `stop`。第一条明确描述“修改后同命令复跑仍失败”，引用失败的 `verify-000002`；第二条仅以“在指定目录以 1 秒超时运行该脚本”为适用条件，并明确 120 秒不构成必要或充分的修复证明。两条仍为 `warning/inferred`，仅保留观察，准入 0 条。

这两次是修复对应反例的定向复验；完整 10 片段报告保留其原始结果，没有覆盖或将两组不同版本输出合成一个批次。结构校验仍不能一般性证明任意自然语言推广，本轮没有将提示约束当成语义正确性的保证。

独立复核确认两个指定反例闭合，另记一项非阻断措辞问题：retry 的 limitation 把投影中的“尝试修改”简写成“修改了实现”。完整合成轨迹有成功编辑，但该编辑事件未进入模型投影引用，严格表述应保留“尝试”。该结果仍仅为观察；这也说明推广评测不能只看 JSON 和引用 ID 是否有效。见 [定向输出逐条复核](candidate-followup-adjudication.json)。
