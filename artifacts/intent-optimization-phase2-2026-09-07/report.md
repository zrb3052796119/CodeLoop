# 意图识别第二轮优化与评测

本轮修复已落地，原有题集的完整解析率提高；新题没有提供可归因于本轮代码的泛化提升证据。主要改动是区分当前请求与背景动作、保留复合任务、补齐文件实体及有明确依据的历史指代。相关回归 2484 项全部通过。

## 真实 LLM 对照

“完整解析”要求主意图、该题标注的动作、肯定/否定、实体、只读边界和顺序全部通过；不等同于仅认对一个意图标签。三个题集独立报告，不合并为总体成功率。

| 题集 | 本轮前完整解析 | 本轮后完整解析 | 主意图正确（前→后） |
| --- | --- | --- | --- |
| 原 50 题，开发集 | 40/50（80%） | 43/50（86%） | 42→43 |
| 上一轮 40 题，现为开发集 | 24/40（60%） | 29/40（72.5%） | 32→35 |
| 本轮独立封存 40 题 | 27/40（67.5%） | 29/40（72.5%） | 28→30 |

原 50 题新增通过 C02、C33、C46、C48，C09 从通过变成超时降级失败；上一轮 40 题新增通过 N03、N20、N21、N33、N39，无严格评分回退。新题新增通过 H03、H09。

**新题的两个新增通过来自模型提议/置信度变化，不能归因于这轮代码。** H03 从低置信度变成接纳，H09 从 test/analyze 变为 debug/analyze。将同一固定提议分别送入旧快照和最终解析器，结果完全一致。两版在新题上禁用 LLM 的逐题操作和评分也一致。因此 67.5%→72.5% 只是两次真实运行的观察值，尚不能证明稳定泛化收益。

## 可重复的规则与实体收益

| 题集，禁用 LLM | 本轮前完整解析 | 本轮后完整解析 | 新增通过 |
| --- | --- | --- | --- |
| 原 50 题 | 31/50 | 34/50 | C33、C46、C48 |
| 上一轮 40 题 | 18/40 | 22/40 | N03、N20、N21、N33 |
| 本轮新 40 题 | 11/40 | 11/40 | 无 |

以上三个禁用模式没有严格评分回退。本轮代码能确定解释的收益包括这七道开发题及新增边界回归。N39 的旧 live 仅缺 `.coveragerc` 实体，本轮补齐后也达到完整解析；禁用模式仍因配置意图缺失而失败。C02 的超时→接纳和 C09 的接纳→超时则属于真实模型运行差异。

- **当前请求与背景动作分开处理。** “解释一下它想解决什么问题”里的“解决”不会覆盖解释请求；“运行脚本时出现了错误，帮我定位原因”中的运行事实不会再生成测试执行操作。同时保留“运行 app.py 时记录所有失败请求”等真正的执行命令及条件处理。
- **复合任务更完整。** 读取源码后分析软件故障原因可保留 DEBUG/ANALYZE；给现有文件增加功能并更新文档时保留两个修改操作；有明确源路径与目标路径的移动请求及其否定可识别。泛化因果分析还要求软件依据，避免把招聘等普通问题标为调试。
- **文件实体与动作识别分离。** 新增共用文件提取 helper，覆盖日志、CSV、SVG、点文件以及明确分隔的中文路径。明确的前后/序号文件指代可选择目标，当前显式文件优先；候选不唯一时不猜测。
- **追加测试只继承可信目标。** 从先前已肯定的 TEST CREATE/UPDATE 操作有效语段提取明确测试主体；背景日志、被否定或取消的请求不能变成当前测试写入目标。没有可确认的历史文档操作时，不凭“一行”等指代臆造文档修改权限。

生产变更限于 `minicode/intent_parser.py`、`minicode/intent_negation.py` 和新增 `minicode/intent_entity_targets.py`；另更新使用说明，新增两组回归测试。没有修改本轮 LLM provider、提示词、校准、置信阈值或全局用户配置。

## 只读误判必须独立看

以下只统计预先标注为只读的题目中，实际解析出的 affirmed CREATE/UPDATE/DELETE/EXECUTE/MOVE/RENAME/MERGE/SPLIT 操作。UNKNOWN 不算误写；它仍可能因未识别请求而评分失败。所有样例只调用解析器，没有执行这些操作。

| 真实 LLM 运行 | 本轮前误写/执行题 | 本轮后误写/执行题 |
| --- | --- | --- |
| 原 50 题 | 无 | C40 |
| 上一轮 40 题 | N10、N21 | 无 |
| 新 40 题中的 23 道只读题 | H33 | H33 |

N10 的错误修改、N21 的错误执行已消除，禁用 LLM 时也可复现这一修复。N10 仍因否定意图标签和引用文件实体缺失而未达到完整解析。

**C40 不能被总分掩盖。** 请求是解释网页按钮文案“执行数据库迁移”，本次 LLM 却给背景文案生成了 CODE/UPDATE。它在前后严格评分中都是失败，因此不出现在“通过→失败”列表中，但实际从只读解析变成了错误写入解析。离线固定同一提议验证：旧快照和最终代码都接纳该 UPDATE；这是既有语义入口缺口在本次输出中暴露，不是本轮新增规则回归，但最终系统仍有此风险。

新题 H33“找出订单编号的生成函数，再解释……”在两版中都把名词短语“生成函数”切成 CODE/CREATE。新题另有 H06/H10/H36/H37 未识别肯定请求；这些 UNKNOWN 与 H33 的实际误写分别记录。

## 尚未解决的问题与后续优先级

1. **最高优先：在每个语段上验证动作授权。** 先区分请求动词、宾语中的动作词、引用材料、过去事实和假设，再接纳规则或 LLM 操作。H33 表明关键词分句仍会把对象当指令；C40 表明引用屏蔽后残留的背景文字仍可能进入语义写入入口。应让写入提议必须绑定当前明确请求证据，并用固定错误提议做对抗回归。
2. **修正过宽的语义跳过与否定范围。** H06/H10 等只读比较/审查没有得到兜底，H36 的正向审查被否定约束吞掉；H13 的“已经不用了”又错误否定了后续明确删除请求。需要区分背景状态和指令否定，同时保留独立的当前请求。
3. **统一任务类别与动作。** 普通脚本执行仍容易标成 TEST/EXECUTE（H14/H20）；日志级别配置可能误入 DEBUG（H17）；SYSTEM 与配置/文档否定标签不完整（C30、N01、N04、N18 等）。不应为提高召回直接放宽高风险操作白名单。
4. **补齐上下文中的多步方案和对象来源。** H38 漏掉“采用第二方案”的实现更新，N37 无法完整选择方案并保留另一项的否定；C50 的文档行目标缺失。反引号包裹的历史双文件指代仍是已知遗漏。应建立带来源和操作归属的上下文对象，逐步替代从整段历史收集关键词。
5. **重新建立未见评估集。** 当前 130 题已全部解盲；下轮可作为回归开发集，不能继续称为独立验证。新代码冻结后另出未见题；若要声称稳定的 LLM 收益，需要事先固定重复次数并保留全部成功、失败和超时。
