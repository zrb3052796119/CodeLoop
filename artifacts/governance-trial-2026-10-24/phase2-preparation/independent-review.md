# Offline acceptance review

The five read oracles cannot pass a response that only repeats the prompt or supplies the expected facts. They require two exact source quotations located inside executed functions, an executable pytest diagnostic, minimum check counts, no skip/xfail/xpass, and observed calls into the actual implementation. Four also require that the same diagnostic produce a real test failure on the historical parent; import/collection errors do not qualify. Image boundaries instead require observations of the actual reject and successful visual-routing outcomes, because the parent lacks this new API.

For each read task, an actual historical-test diagnostic was accepted, while incorrect facts, answer-only output, enough hardcoded assertions with no implementation calls, and an xfail-marked diagnostic were rejected. The five result rows and their logs are saved. These are targeted false-positive checks, not a proof against malicious submitted Python. Call-count profiling itself can be deceived by hostile code; the study assumes non-adversarial attempts.

All 16 prepared oracles passed the existing host `implementation_judge` ABI and process cleanup checks. This preflight deliberately uses reference solutions and disables the generated-regression requirement; it is not a claim that a model solved a task. Formal write/refactor trials retain the default requirement for generated regressions, the historical oracle, nonempty authorized implementation changes and scope checks.

The adapter regression selected six existing test files: 114 passed. Its single and auto lifecycle checks use the real runtime, dispatcher and transport with offline SSE bytes in place of HTTP; a socket guard rejects external connections. Both arms retain GLM5.3 Flash for all roles, remove economic caps, preserve input/output/call accounting, and leave read-only source workspaces unchanged. The test logs do not certify the whole current repository; Phase0 is a separate prerequisite.

The separate review of the new scheduler audit binding found no future/older Analyst evidence bypass: matching uses only completed prior dispatches, in reverse order, and requires the exact latest handoff inputs. Policy versions below 6 still reject the unplanned analysis. The v6 trace recognizer requires an actual failed verifier transition and a completed diagnostic lifecycle. Nine relevant scheduler tests passed; this review did not modify scheduler code.

Material relocation replaces only the four oracle parent-directory literals. Source contents, test bytes, predicates and selectors are unchanged. `rebuild.py` verifies the parent source inventory and then the existing runner copies that dependency outside the public workspace and revalidates its hash before execution. Reference diagnostics, answer facts, oracle code, source reference trees and repair patches never become public task files. OS-level hostile access remains out of scope and is documented rather than claimed to be blocked.
