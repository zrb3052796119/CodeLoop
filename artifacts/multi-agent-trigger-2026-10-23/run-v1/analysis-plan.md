## 范围与来源

Gen-2 六格工程门已通过（5/6；single 3/3、explicit 2/3，结果提交 `94c06e26`）。用户于 2026-10-23 明确授权“冻结新八题，继续 Phase 2”。本轮沿用已授权的智谱端点 `https://open.bigmodel.cn/api/coding/paas/v4/chat/completions` 和模型 `glm-5.3-flash`。

旧合成八题及 auto 原始轨迹已于 10 月 19 日删除，无法按原题重跑。这是独立新一代合成任务包，称为 **trigger-gen2**，不是旧八题复现；与旧合成 0/24、旧真实 0/16、gen-2 工程六格及全部历史数字不可直接比较。前六题是具有合理独立调查或隔离实现空间的任务，后两题是已知位置的单文件负例。正例标签表示存在可用的委派机会，不表示直接实现不合理。

任务、缺陷、参考实现和隐藏验收均为本轮人工构造；不声称来自真实历史提交。任务不复用 gen-2 三题的换行/EOF 坐标、资源拥有权或完整请求预算缺陷。公开题目不包含正负标签、是否委派的要求、参考解法或隐藏 oracle；不人为填充文件、强迫读取八批或先行支付分析。所有题目均要求实际修复并新增回归测试，父代理自行选择直接工具或 task。

## 离线有效性与隔离

每题以相同解释器、同字节隐藏 oracle 验证：基线公开兼容测试通过；基线隐藏验收因目标行为失败；参考修复公开测试和隐藏验收通过。证明保留退出码、结构化行为断言、前后源码哈希与测试字节，导入失败、空测试或任意非零退出不算目标反例。没有模型参与选题或离线调试，不用付费结果筛选题目。

实际工作区仅投影公开文件、题目、写范围和公开验证命令。参考修复、标签、离线证明和 oracle 留在裁判端。所有题目必须新增 `tests/test_eval_regression.py`，独立运行全部收集项；至少一项通过，禁止 skip/xfail/筛选收集。共同裁判在交付副本上另计 120 秒，检查导入来源、隐藏验收、生成测试、真实生产修改、范围及清理。该成功率作为独立结果报告，不取代触发门。

## 冻结执行条件

- 8 题 × auto 组 × 1 次，共恰好 8 格，串行执行。固定种子 `20261023` 打乱，具体顺序写入 manifest；不因上一格失败而挑选下一格。
- 全部父代理均保留直接编码工具和 task，使用默认 continuous 执行，不启用旧 bounded 阶段模式，不注入 explicit 协作指令。
- 模型 `glm-5.3-flash`，temperature=0，HTTP 重试=0；父子角色继承同一模型。explore/plan/general 累计角色上限显式设为 0，表示没有额外累计角色上限，仍受共享预算与生产 Assignment 约束。
- 每格父子共享最多 40 次物理请求、500000 token、600 秒 Agent 执行时间。输出上限 8192 token；连接、空闲、单请求超时分别 30/120/300 秒；沿用 5 USD 成本安全上限。外部裁判预算单列，不延长 Agent 时间。
- 完整宿主源码、运行器、独立审计器、依赖声明、任务、预注册与材料哈希在运行前冻结并提交。运行只能使用校验后的宿主副本；父入口与 child 入口都须在 provider 初始化前核验真实提交中的冻结字节。
- 当前宿主包含 Phase 0/1/2 修复与用户已有背景修改，逐文件记录实际字节。由于没有同题修前对照，本实验不能单独识别 Phase 2 的因果增益，也不能证明多 Agent 高于单 Agent。
- 完整保留实际请求/响应、物理用量、task 启动与控制调用、子代理身份、父子关系、宿主送达确认、清理与裁判记录。父请求正文以实际物理 call ID 绑定，用于核对动态提示是否出现；不记录认证 headers 或凭证。

## 触发口径与继续门

分母固定为全部八格，包括失败、超时、拒绝、未触发和无效格。不得只取六个 opportunity 或剔除失败格提高比例。

**有效触发**：至少一个真实子代理发生完成的物理模型请求，并有宿主证明其结果已送回父代理。只读 explore/plan 或写路径 workflow 均可计入；只调用 task 控制接口、仅声称委派、准入即拒绝、无物理执行或无送达均不计入。对 workflow 子角色，必须有对应父 workflow 的送达证据。失败或partial结果可以证明采用；合法的异步取消终态若无返回结果，保留为有效失败观察但不计触发。触发不要求修复成功，修复结果另报。

**负例误触发**：在两道 single-file-negative 中，父代理任何委派启动请求都算误触发，包括随后被准入拒绝的请求。只有明确的纯 poll/cancel 控制动作不算启动：须有非空subagent_id，且不混入prompt、agent_type、写范围等启动参数。缺省action按run计，未知action或无法解析而不能排除启动意图的task请求保留为ambiguous，使零误触发证明不成立，不得静默记为零。

全部满足才通过 Phase 2：

1. 恰好八格终态、八格独立审计有效，用量、范围、协议、清理和证据完整。
2. 有效触发至少 **2/8（25%）**。
3. 两道负例的委派启动请求均为 **0**，且没有不能排除的启动请求。

通过只表示该模型、预算和任务包上出现了选择性的真实采用，可进入另行预注册的正式对照准备；本入口不自动扩展为 48 次。未过门则记录失败并停止扩展，不换题、换模型、补抽轮次或调整口径。

## 诊断与报告

逐格报告启动请求数、真实子代理数、送达数、主触发判定、修复成功、请求/token/墙钟成本、错误与未知用量。主 Agent、只读角色、Executor、其他工作流角色分别归因。

将静态系统/task 指引和宿主动态进度建议区分开。若动态建议实际进入父请求，记录该请求响应中的首批工具选择与其后是否启动委派；只做描述，不将后续委派自动归因于建议。不达到八批读取、先编辑、预算/时间压力或任务提前完成时，动态建议未出现是可解释结果，不算日志缺失。完整日志支持核查提示呈现与选择，不能据此读出模型未表达的动机。

当前共同宿主还可能运行既有的原生completion/coverage审查循环，旧物理账本会将这些未经过task的调用归入main。它们的用量和正文同样保留，但不计task采用；依据实际工具schema区分这些审查输入与可委派的父请求。复制到审查上下文的动态提示不重复计为新的父提示呈现；报告main归因成本时说明这一边界，不改宿主规则以省掉这些请求。

所有失败、预算拒绝、超时、缺失用量和清理问题保留。存在持久调用证据的格不得重跑；不能安全继续时，保留已发生记录并标明不完整。未知用量不记零，审计无效阻断过门。历史任务残缺与新题性质明确写入最终结论。
