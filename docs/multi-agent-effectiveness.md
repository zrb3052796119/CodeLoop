## 从调查进入实现：已落地的修复

这些改动针对已复现的执行障碍，保留原有权限、证据绑定、确定性验证与隔离回写：

1. **减少重复调查。** 委派写任务直接进入 workflow，不再默认先调用外部 Plan；低风险限定修改走 Executor→Verifier，需审查的路线才启用 Analyst/Reviewer。Plan 仍服务于明确的调查问题，其自由文本摘要不能代替已签发的 Analyst 证据。交接提示要求简短、字段完整，并遵守 3,800 字符限制。
2. **让已读证据可用于修改。** 连续读取和预算压力触发有次数上限的反馈；仅对已确认的实现任务启用，不强迫只读任务写入。旧读取正文在内存中缩短，同时保留最新批次和有限源码窗口；不裁剪权威回执或验证证据。Executor 可在原权限内 grep，read_file 支持行范围，grep 合并重叠上下文；已知目标路径时优先定位必要定义、调用和测试。
3. **按剩余额度分配实现阶段。** 无显式角色上限时，Executor 从启动时的共享剩余调用量分配本地上限，为必经 Reviewer 和父 Agent 最终响应留量。Assignment 声明、实际工作轮数和物理请求准入使用同一份额度；显式配置不会被扩大，重试与收尾也计入。本轮验证的全局额度仍为 40 次请求、500,000 token 估算准入、600 秒，不保证剩余额度一定足以完成修复。
4. **及时验证和交接。** 根据真实剩余执行时间，在 180/90 秒阈值给出有界提醒。严格角色必须在仍可调用工具的工作轮提交结果；工具禁用的收尾回答不能替代结果工具。进程回收分开记录冻结与退出确认两个阶段，清理不完整仍禁止验收和后续试次。

最终工作区版本的相关联合回归为 **883 项通过（49.18 秒）**，Ruff F 与差异空白检查通过。这证明已覆盖的行为与边界得到验证，不代表真实模型交付率提高。
