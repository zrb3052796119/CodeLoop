# CodeLoop 快速上手

目标：在自己的电脑完成安装、本地自检、配置个人 API，然后在一个练习项目中完成首次对话。本文以交付压缩包解压后的目录名 `CodeLoop` 为例。产品叫 CodeLoop，Python 包名是 `minicode-py`，Python 模块仍叫 `minicode`。

## 1. 准备与安装

需要 Python **3.11 或更高版本**；建议使用 Python 3.12。首次安装需要能够访问 Python 软件包源。使用真实模型还需要你自己的 provider 账号、可用模型 ID、API key 和对应接口地址。API 使用费用由该账号承担。

把 `CodeLoop` 解压到一个准备长期保留的位置。下面所有 `/path/to/...`、`C:\path\to\...` 都要换成自己的实际路径。无需激活虚拟环境，直接调用其中的 Python，可以避免 Windows PowerShell 的脚本执行策略问题。

macOS / Linux：

```bash
cd "/path/to/CodeLoop"
python3 --version
python3 -m venv .venv
CODELOOP_DIR="$PWD"
CODELOOP_PY="$CODELOOP_DIR/.venv/bin/python"
"$CODELOOP_PY" -m pip install .
"$CODELOOP_PY" -m pip show minicode-py
"$CODELOOP_PY" -m minicode.main --help
```

Windows PowerShell：

```powershell
Set-Location "C:\path\to\CodeLoop"
py -3.12 --version
py -3.12 -m venv .venv
$codeLoopDir = (Get-Location).Path
$codeLoopPy = Join-Path $codeLoopDir ".venv\Scripts\python.exe"
& $codeLoopPy -m pip install .
& $codeLoopPy -m pip show minicode-py
& $codeLoopPy -m minicode.main --help
```

如果 Windows 只装了 Python 3.11，把两处 `py -3.12` 改成 `py -3.11`。如果 Linux 提示缺少 `venv` 或 `ensurepip`，先安装系统发行版对应的 Python venv 组件，再重试。

**成功标志：** `pip show` 能找到 `minicode-py`；帮助中列出 `--install`、`--validate-config`、`--resume` 等选项。普通使用不需要开发依赖、Node.js、前端构建或额外模型文件。

本文采用普通安装 `pip install .`。以后更新源码后，要再运行一次此命令；源码变化不会自动更新已安装包。虚拟环境不适合直接搬家，移动整个目录后请重建 `.venv` 并重新安装。

## 2. 先做不使用 API 的本地自检

仍在 `CodeLoop` 目录执行：

macOS / Linux：

```bash
"$CODELOOP_PY" docs/handoff/tools/self_check.py
```

Windows PowerShell：

```powershell
& $codeLoopPy docs/handoff/tools/self_check.py
```

自检使用临时用户目录、临时项目和 mock 模型，隔离个人配置、阻断非本机网络连接及额外子进程，并关闭非本次检查目标的系统沙箱探针；不需要填写真实 key。**成功标志：** JSON 报告中 `status` 为 `PASS`，进程退出码为 0。可在命令末尾加 `--report self-check.json` 保存报告。

它检查安装后的入口、静态资源和 mock 列出文件链路，**不证明真实模型可用，不覆盖真实终端交互，也不代表完整测试套件已经通过**。自检要求本文的普通安装；如果使用了 `pip install -e .`，会明确拒绝，请改为普通安装再运行。

不要用单独设置 `MINI_CODE_MODEL_MODE=mock` 来代替这一步。该开关只替换模型适配器，已有的 MCP 或可选远程能力仍可能影响启动。

## 3. 配置你自己的主模型

推荐先从交付包的简化模板开始：[`config/.env.example`](config/.env.example)。模型配置保存在**用户主目录** `~/.mini-code/.env`，不会自动读取目标项目自己的 `.env`。

下面的命令只在配置不存在时复制模板；已有配置会保留。不要拿别人的 `.env`、`settings.json` 或整个 `~/.mini-code` 目录替换自己的配置。

macOS / Linux：

```bash
mkdir -p "$HOME/.mini-code"
chmod 700 "$HOME/.mini-code"
if [ ! -e "$HOME/.mini-code/.env" ]; then
  cp "$CODELOOP_DIR/docs/handoff/config/.env.example" "$HOME/.mini-code/.env"
else
  echo "已有配置，请对照模板手动编辑，不覆盖。"
fi
chmod 600 "$HOME/.mini-code/.env"
```

Windows PowerShell：

```powershell
$codeLoopConfigDir = Join-Path $HOME ".mini-code"
$codeLoopConfigFile = Join-Path $codeLoopConfigDir ".env"
New-Item -ItemType Directory -Force $codeLoopConfigDir | Out-Null
if (-not (Test-Path $codeLoopConfigFile)) {
    Copy-Item (Join-Path $codeLoopDir "docs\handoff\config\.env.example") $codeLoopConfigFile
} else {
    Write-Host "已有配置，请对照模板手动编辑，不覆盖。"
}
notepad $codeLoopConfigFile
```

用文本编辑器打开该文件，按 provider 提供的信息填入模型 ID、接口基础地址和 key；保存为 **UTF-8，无 BOM**。默认模板采用 `custom`（OpenAI-compatible）配置；不要把占位内容当成可用账号。其他 provider 对应字段如下：

| `MINI_CODE_PROVIDER` | 必填凭据 | 地址字段 | `MINI_CODE_MODEL` |
| --- | --- | --- | --- |
| `custom` | `CUSTOM_API_KEY` | `CUSTOM_API_BASE_URL` 必填 | provider 实际开放的模型 ID |
| `openai` | `OPENAI_API_KEY` | `OPENAI_BASE_URL`，可省略以使用内置默认地址 | provider 实际开放的模型 ID |
| `anthropic` | `ANTHROPIC_API_KEY` 或 `ANTHROPIC_AUTH_TOKEN` | `ANTHROPIC_BASE_URL`，可省略 | provider 实际开放的模型 ID |
| `openrouter` | `OPENROUTER_API_KEY` | `OPENROUTER_BASE_URL`，可省略 | OpenRouter 模型 ID |

主模型一次选择一种 provider。每个 key 只保留一条有效赋值；修改已有行，不要在文件末尾重复追加。接口地址填写基础地址，通常不要填到 `/chat/completions`；是否包含 `/v1` 以该 provider 的要求为准。远程地址要求 HTTPS，HTTP 只接受 `localhost`、`127.0.0.1` 或 `::1`。不要在 URL 中嵌入用户名、密码、查询参数或片段。

也可使用交互安装向导代替手动填配置：

```bash
# macOS / Linux
"$CODELOOP_PY" -m minicode.main --install
```

```powershell
# Windows PowerShell
& $codeLoopPy -m minicode.main --install
```

向导依次询问模型、provider、基础地址和 key，更新相应配置项，并安装快捷启动器。它不会安装 Python 依赖，也不会验证远程 key。macOS / Linux 启动器位于 `~/.local/bin/minicode-py`；Windows 位于 `~/.mini-code/bin/minicode.bat`。即使没有把它加入 PATH，仍可沿用本文的显式 Python 命令。

## 4. 检查本地配置

macOS / Linux：

```bash
"$CODELOOP_PY" -m minicode.main --validate-config
```

Windows PowerShell：

```powershell
& $codeLoopPy -m minicode.main --validate-config
```

**成功标志：** 输出 `Status: OK`，且摘要中的模型、provider 符合你的选择。看到 `Status: ERRORS` 就按提示修复。当前命令即使发现错误也可能返回退出码 0，不能只看退出码。

该检查只校验本地配置，不发起 API 请求。`Unknown model` 是内置模型名单之外的提醒；模型 ID 确实来自 provider 时，不能仅凭这个提醒认定模型不受支持。

## 5. 在练习项目中完成首次真实对话

**当前工作目录就是 Agent 的目标项目。** 安装目录与目标项目可以不同。建议首次用一个不含敏感文件的练习目录，确认模型与审批体验后再进入正式项目。

macOS / Linux：

```bash
mkdir -p "$HOME/codeloop-demo"
cd "$HOME/codeloop-demo"
"$CODELOOP_PY" -m minicode.main
```

Windows PowerShell：

```powershell
$codeLoopDemo = Join-Path $HOME "codeloop-demo"
New-Item -ItemType Directory -Force $codeLoopDemo | Out-Null
Set-Location $codeLoopDemo
& $codeLoopPy -m minicode.main
```

先输入：

```text
不调用任何工具，用一句中文说明你可以如何帮助我理解一个 Python 项目。
```

**成功标志：** 得到模型的正常中文回答，没有认证、连接或模型不存在错误。这一步由接收同学使用自己的 API 执行，会产生真实调用费用；交付前的 mock 自检不能替代它。

然后可尝试一个小范围任务：

```text
在当前练习目录创建 hello.py，运行后打印 Hello, CodeLoop!。如需执行命令，先说明命令，并在完成后告诉我如何验证。
```

按屏幕提示核对并处理审批。检查生成文件，再自行执行：

```bash
# macOS / Linux，仍在练习目录
"$CODELOOP_PY" hello.py
```

```powershell
# Windows PowerShell，仍在练习目录
& $codeLoopPy hello.py
```

应输出 `Hello, CodeLoop!`。模型回复“完成”不能代替文件与运行结果的检查。输入 `/exit` 退出。

## 6. 第二天继续使用

新开终端后，重新指定安装目录中的 Python，再进入目标项目。

macOS / Linux：

```bash
CODELOOP_PY="/path/to/CodeLoop/.venv/bin/python"
cd "/path/to/your/project"
"$CODELOOP_PY" -m minicode.main
```

Windows PowerShell：

```powershell
$codeLoopPy = "C:\path\to\CodeLoop\.venv\Scripts\python.exe"
Set-Location "C:\path\to\your\project"
& $codeLoopPy -m minicode.main
```
