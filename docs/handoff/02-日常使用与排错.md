# CodeLoop 日常使用与排错

本文假设已完成 [快速上手](01-快速上手.md)。以下命令中的 `$CODELOOP_PY`（macOS / Linux）或 `$codeLoopPy`（PowerShell）指向安装目录 `.venv` 里的 Python。每次新开终端都要重新设置该变量。除安装和自检外，都在**希望 Agent 处理的目标项目目录**运行。

## 1. 一次任务怎么交代

先说目标，再说可修改范围与验收方式。例如：

```text
请先阅读项目入口和相关测试，解释当前登录流程，不要修改文件。
```

```text
修复 src/parser.py 对空输入的处理，只改相关实现和测试。沿用现有接口，完成后运行相关测试，列出改动和仍未验证的部分。
```

在正式项目中，开始前查看 Git 状态并保留已有改动；结束后检查 diff 和实际测试结果。权限提示出现时，按界面显示的具体选项操作。任务涉及自己的项目命令时，该项目的依赖环境仍需单独准备，CodeLoop 的虚拟环境不会自动包含它们。

## 2. 常用交互命令

这些命令是在 CodeLoop 对话框内输入的，不是在系统终端直接执行。

| 输入 | 作用 |
| --- | --- |
| `/help` | 查看命令分组；输入 `/` 浏览，Tab 补全 |
| `/status`、`/context` | 查看应用状态与上下文使用情况 |
| `/ls`、`/read README.md` | 列文件、读取文件 |
| `/grep TODO::src` | 在 `src` 中搜索 `TODO` |
| `/tools` | 查看当前可用工具 |
| `/skills`、`/mcp` | 查看发现的 Skill 与 MCP 状态 |
| `/config`、`/config-paths` | 查看配置诊断和配置文件位置 |
| `/model` | 查看模型；切换 provider 建议退出后修改完整配置再重启 |
| `/cost` | 查看本地用量与费用报告；最终账单以 provider 为准 |
| `/memory`、`/tasks` | 查看经验记忆与当前任务列表 |
| `/mode` | 查看权限模式 |
| `/mode plan` | 切换只读计划模式 |
| `/mode default` | 回到默认权限模式 |
| `/history` | 查看近期输入历史 |
| `/transcript-save session-notes.txt` | 将当前对话文本保存到目标项目文件 |
| `/retry` | 重试最近的自然语言任务；可能再次产生 API 费用 |
| `/clear` | 清空当前显示，不等于删除历史、会话或 Memory |
| `/exit` | 退出 |

`/model <模型名>` 会把模型名写入全局 `.env`，对可识别的模型名还可能自动改写 provider；它不会补齐匹配的 endpoint 和凭据。更换厂商或使用 custom 端点时，建议退出后整体编辑并检查这几项。`/mode bypass` 会放宽审批；遇到权限错误时，先核对请求本身与授权范围。

## 3. 恢复会话

在真实交互终端中运行，不要把这些命令放进管道；当前 `--list-sessions` 和 `--resume` 的处理在 TTY 分支中。

macOS / Linux：

```bash
"$CODELOOP_PY" -m minicode.main --list-sessions
"$CODELOOP_PY" -m minicode.main --resume
# 用列表中的真实 ID 替换 SESSION_ID
"$CODELOOP_PY" -m minicode.main --resume SESSION_ID
```

Windows PowerShell：

```powershell
& $codeLoopPy -m minicode.main --list-sessions
& $codeLoopPy -m minicode.main --resume
& $codeLoopPy -m minicode.main --resume SESSION_ID
```

无参数 `--resume` 恢复当前工作区最近的会话；指定 ID 时务必确认当前目录仍是原项目。正常退出后应看到 `Session saved: ...`。如果看到 `Session save deferred; will retry.`，先检查存储权限和磁盘空间，不要据此认定会话已保存。

## 4. 单次非交互运行（Headless）

适合只读分析或已有明确授权的自动化任务。它没有交互审批窗口，遇到需要新授权的操作可能被拒绝。先用小任务验证。

macOS / Linux：

```bash
"$CODELOOP_PY" -m minicode.headless "只读分析当前项目，说明入口与主要模块，不要修改文件。"
```

Windows PowerShell：

```powershell
& $codeLoopPy -m minicode.headless "只读分析当前项目，说明入口与主要模块，不要修改文件。"
```

也支持从标准输入读取完整 prompt。例如 macOS / Linux：

```bash
printf '%s\n' '只读解释 README.md 的安装步骤。' | "$CODELOOP_PY" -m minicode.headless
```

当前 headless **没有** `--prompt`、`--output` 或 `--help` 参数解析；命令后的所有内容都会作为 prompt。检查输出是否包含预期回答或任务结果。部分运行异常会以 `Error: ...` 文本返回而非非零退出码，自动化验收不能只看进程退出码。

## 5. 打开本地 Dashboard

Dashboard 与 CLI 共用已安装的 Python 包，界面静态资源随包提供。仍从目标项目目录启动：

macOS / Linux：

```bash
MINI_CODE_GATEWAY_HOST=127.0.0.1 MINI_CODE_GATEWAY_PORT=8080 "$CODELOOP_PY" -m minicode.gateway
```

Windows PowerShell：

```powershell
$env:MINI_CODE_GATEWAY_HOST = "127.0.0.1"
$env:MINI_CODE_GATEWAY_PORT = "8080"
& $codeLoopPy -m minicode.gateway
```

看到 `CodeLoop gateway listening on http://127.0.0.1:8080` 后，在浏览器打开 [本地 Dashboard](http://127.0.0.1:8080)。首次没有历史时，空列表是正常结果。保持启动终端运行；按 Ctrl+C 停止服务。使用页面聊天会调用你配置的模型。

默认监听本机地址和 8080 端口。端口被占用时，把上面两平台命令的 `8080` 改为 `8081`，浏览器也改为相应地址。当前 gateway 不解析 `--host` / `--port`；必须使用上述**进程环境变量**，把它们写入全局模型 `.env` 不会生效。

工作区默认是启动目录。已有 `MINI_CODE_DASHBOARD_WORKSPACE` 环境变量会改变 Dashboard 绑定的工作区；出现“显示错项目”时检查该变量。普通使用建议保持未设置，并从目标项目启动，这也避免与 `/run` 使用的进程当前目录不一致。

保持本机 `127.0.0.1` 使用即可。非本机部署涉及鉴权、网络访问和审批能力差异，不在这份同学试用交付范围内。

## 6. 配置优先级与数据位置

主模型配置优先级从高到低为：

1. 当前进程环境变量。
2. `~/.mini-code/.env` 中允许的模型配置项。
3. 旧格式 `~/.mini-code/settings.json`，再兼容 `~/.claude/settings.json`；执行过模型配置迁移后，这一模型回退会关闭。

显式设置为空值也可能覆盖低优先级配置。若修改 `.env` 后仍使用旧模型，检查终端或启动脚本是否设置了相同变量。项目里的普通 `.env` 不参与主模型、embedding 或子 Agent 的凭据和地址路由。

MCP 是另一套合并规则：`~/.claude/settings.json` → `~/.mini-code/mcp.json` → 项目 `.mcp.json` → `~/.mini-code/settings.json`；后者覆盖前者的同名字段。已有 Claude 兼容配置可能带来你没有在 CodeLoop 中新建的 MCP 或 Skill。用 `/mcp`、`/skills` 核对实际结果。

下表中的 `~` 是当前系统账号的主目录；Windows 通常对应 `C:\Users\你的用户名`。

| 位置 | 内容与处理方式 |
| --- | --- |
| `~/.mini-code/.env` | 私人 API key、模型配置；不作为交付附件 |
| `~/.mini-code/settings.json`、`permissions.json`、`mcp.json` | 结构化设置、权限、MCP；可能包含私人信息或凭据 |
| `~/.mini-code/USER.md` | 跨项目偏好 |
| `~/.mini-code/history.json` | 输入历史，可能含项目或业务信息 |
| `~/.mini-code/sessions/`、`sessions_index.json` | 持久化会话与索引 |
| `~/.mini-code/minicode.log` | 运行日志，排错时取相关时间段 |
| `~/.mini-code/dashboard/workspaces/<工作区ID>/` | 按工作区归档的运行记录等 Dashboard 数据 |
| `~/.mini-code/memory/` | 跨项目经验记忆 |
| 目标项目 `.mini-code-memory/` | 项目共享经验；提交前审阅内容 |
| 目标项目 `.mini-code-memory-local/` | 项目本地经验，通常不要提交 |
| 目标项目 `.mini-code/USER.md`、`.mini-code/skills/` | 项目偏好和 Skill |
| `~/.mini-code/skills/` | 个人 Skill；另兼容项目与用户的 `.claude/skills/` |

卸载 Python 包不会自动删除这些数据。备份会话时保留个人权限并妥善保管；向别人发问题复现材料时，选取必要片段并去掉 key、私有源码、业务数据和个人路径，不要整目录发送。

## 7. 可选 Skill 与 MCP

这些不是首次运行的前提。Skill 是带 `SKILL.md` 的工作流程目录，MCP server 是需要额外安装和配置的外部工具进程。先用基础功能，再按实际任务添加。

macOS / Linux 示例：

```bash
"$CODELOOP_PY" -m minicode.main skills list
"$CODELOOP_PY" -m minicode.main skills add "/path/to/a-skill" --project
"$CODELOOP_PY" -m minicode.main mcp list
"$CODELOOP_PY" -m minicode.main mcp list --project
```

PowerShell 对应写法为 `& $codeLoopPy -m minicode.main ...`。`--project` 将配置或 Skill 安装到当前目标项目。只有清楚所添加工具的来源与用途后再启用；不需要为普通聊天配置 embedding、Hybrid Memory、单独子 Agent 模型或远程 reflection。

## 8. 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| `minicode-py: command not found` | 使用虚拟环境 Python 的绝对路径运行 `-m minicode.main`；不依赖 PATH |
| `No module named minicode` | 核对是否用了 CodeLoop `.venv` 中的 Python；在安装目录用同一解释器重新执行 `-m pip install .` |
| PowerShell 拒绝 `Activate.ps1` | 无需修改系统执行策略，使用 `& $codeLoopPy ...` |
| `No model configured` / key 未配置 | 编辑用户目录 `.mini-code/.env`，确认 provider 与 key 字段匹配；目标项目 `.env` 无效 |
| `private_env_directory_permissions_unsafe` / `private_env_permissions_unsafe` | macOS / Linux 执行 `chmod 700 ~/.mini-code`、`chmod 600 ~/.mini-code/.env`；保持为自己拥有的普通目录和文件 |
| `private_env_duplicate_key` | 配置同一个 key 出现多次，保留一条有效赋值 |
| `private_env_key_invalid` / `private_env_utf8_invalid` | 保存为 UTF-8 无 BOM，使用 `KEY=VALUE`，不要复制 Markdown 围栏；若是符号链接错误，改用真实普通文件 |
| `Status: OK`，仍报 401 / 403 | 本地配置检查不能验证 key；检查账号、key、权限及 endpoint 是否属于同一 provider |
| 模型不存在、404 或协议不匹配 | 核对模型 ID、API 类型、基础地址，以及 `/v1` 是否符合 provider 要求；更换模型时同步检查 provider |
| 429 / 配额耗尽 / 超时 | 查看 provider 余额、速率限制和网络；减少并行或任务规模后重试，重试可能产生费用 |
| 修改配置后没变化 | 完全退出并重新启动；检查进程环境变量是否覆盖了文件；检查诊断摘要中的实际模型 |
| 回复固定英文 `This is a minimal MiniCode Python shell.` | 当前用了 mock；检查并移除 `MINI_CODE_MODEL_MODE=mock` 后重新启动真实模式 |
| Headless 无法写文件或运行命令 | 它不能展示新的交互审批，改用交互 CLI 处理需要授权的任务 |
| 找不到 Skill 或 MCP server 启动失败 | 用 `/skills`、`/mcp` 检查目录和状态；确认外部程序在当前进程 PATH 中及其独立依赖已安装 |
| Dashboard 端口占用 / 页面打不开 | 确认服务终端仍在运行、地址端口一致；必要时改成 8081；不要传 `--port` |
| Dashboard 数据与当前项目不符 | 核对启动目录及 `MINI_CODE_DASHBOARD_WORKSPACE`；工作区数据按路径分组 |
| 会话保存失败或找不到恢复项 | 查看退出时的保存提示、磁盘空间、用户目录权限；在原项目目录用交互终端执行恢复命令 |

需要更详细的 CLI 日志时：

```bash
# macOS / Linux
"$CODELOOP_PY" -m minicode.main --log-level DEBUG
```

```powershell
# Windows PowerShell
& $codeLoopPy -m minicode.main --log-level DEBUG
```

Headless 使用进程环境变量 `MINI_CODE_LOG_LEVEL=DEBUG`。交互界面会尽量把诊断写入 `~/.mini-code/minicode.log`，因此屏幕没有报错并不表示日志为空。

反馈问题时附上：操作系统、Python 版本、交付包版本或日期、入口（CLI / Headless / Dashboard）、可复制步骤、预期与实际结果、错误原文及脱敏日志片段。说明本地自检和真实 API 测试分别是否通过，可帮助快速判断是安装、配置、provider 还是任务执行问题。
